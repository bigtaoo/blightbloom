### The gates were green and the log had a hole in it

`npm run check:docpaths` and `npm run check:roadmapindex` both passed at the start of the pass, and
the work of 2026-09-20/21 — a live freeze report, its fix, the assembly test that followed it and
a `design/10` annotation, all merged in PR #31 — had **no work-log volume at all**. Neither gate
can see that, and the reason is worth stating once: `checkRoadmapIndex` runs from the VOLUMES to
the index (*"is every dated section indexed?"*), so a pass that never wrote a volume is a pass it
has nothing to ask about. The volume is now [76](76-2026-09-20-run-clock-freeze.md), written from
the commits, and both index views carry it.

**There is no cheap gate for this** — the honest check is `git log --since=<last volume's date>`
against `ls design/roadmap/`, and it wants a human to decide what counts as a pass. Recorded as
the tell rather than as a gate: the log's last volume is three days older than `main`'s last
commit.

### Layer 7 existed for four weeks before anything named it

Not a split finding — a gap the split made visible. The 2026-09-20 freeze got through because
`run.online` is written by one controller, read by a second and leaked by a screen owned by a
third, and each of those three suites stubs the other two. The test that caught it,
`client/src/game/gameRunClock.test.ts`, joined **nine files that have been doing exactly this since
2026-08-25** — `client/src/game/game*.test.ts`, 67 cases, each headed *"end to end through
`Game`"* — and `design/18` had never mentioned them. So the layer that catches a cross-controller
defect was a habit somebody had to already know about, in the one document whose job is to say what
stops each class of defect. It is now Layer 7, with the two rules that case paid for: **assert the
observable, never the mechanism**, and **ship the control with the case**.

### `design/rendering/03-occlusion-and-doors.md`: the named gap volume 65 deferred

Closed exactly as that volume specified, which is the argument for writing a deferral down in
enough detail: 1,046 lines → [`03-occlusion.md`](../rendering/03-occlusion.md) (333) and
[`04-doors.md`](../rendering/04-doors.md) (722), with `04-floor-arena-void` → `05` and
`05-character-and-objects` → `06`. 22 references followed the rename.

**Two rules for the history that references a renamed file**, both exercised here after the first
sweep got one of them wrong:

- **A pointer follows the file; a claim does not.** The three roadmap volumes that cite this doc as
  *"see X for the mechanism"* were repointed — at `04-doors.md`, not `03-occlusion.md`, since all
  three are about doors. But volume 65's *"`design/rendering/03-occlusion-and-doors.md` is 1,046
  lines"* is a measurement of a named file on a date, and a blanket path rewrite turned it into a
  statement that was never true. Reverted, and the same for `ROADMAP.md`'s summary of it.
- **A closed gap gets a forward pointer where it was named**, not a rewrite: volume 65's named-gap
  bullet now carries a `Closed 2026-09-21` note, and the by-date index line that repeats the gap
  carries the same.

### `design/01-rendering.md` says it carries every heading, and it did not
